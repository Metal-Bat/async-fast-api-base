# OBS-002 — Resolve structlog and duplicate FastAPI telemetry

Backlog: OBS-002
Date: 2026-10-02
Area: core/observability

## Summary

The telemetry handler now removes structlog's internal formatter metadata from an isolated copy
of each log record. This fixes invalid `logging.Logger` attribute warnings without changing the
record received by console/file handlers. FastAPI native telemetry is disabled because the project
already owns exporters and request instrumentation. Real Compose delivery is now verified.

## Why

`ProcessorFormatter.wrap_for_formatter` attaches `_logger` (a Python Logger instance) and `_name`
to logging records. OpenTelemetry treats nonstandard record fields as export attributes, so the
Logger caused an invalid-type warning on every structured request/response log. OBS-001 prevented
those diagnostics from feeding back into export but did not remove their original cause.

The supplied logs also contained binary `BadStatusLine` and HTTP connection-reset export errors.
Both the current source and the inspected `sample_backend:latest` image import gRPC exporters;
no application containers were running. The initial historical process could not be inspected. A follow-up real Compose startup
reproduced the HTTP failures and identified FastAPI native lifespan auto-configuration as the cause.

## What Changed

- `_TelemetryLogFilter` retains SDK/exporter diagnostic exclusion and returns a shallow LogRecord
  copy with `_logger` and `_name` removed. Only the OTLP handler receives this copy. Application
  body, trace context, and other attributes remain intact; local formatter metadata is preserved.
- Extended the existing provider regression with a real structlog event and in-memory OTel
  processor. Assert metadata is absent in export and retained for the subsequent local handler.
- README explains metadata handling and includes binary BadStatusLine in protocol troubleshooting.
  No protocol or port change was needed: Compose remains gRPC on 4317, with HTTP separately on 4318.
- `src/main.py` disables native FastAPI `auto_configure`, tracing, metrics, logs and operation spans.
  The existing `core.observability` providers and FastAPIInstrumentor retain signal ownership,
  avoiding duplicate exporters and request instrumentation.

## Architecture

No architecture change. Filtering remains local to the telemetry handler.

## Compatibility

Requires the project's existing Python 3.14 runtime, which supports filters returning replacement
records. No dependencies, API contracts, migrations or configuration defaults changed. Internal
formatter fields intentionally disappear from exported attributes. Recreate/rebuild services to
load updated source where reload or the Compose source bind mount is not in use.

### Follow-up: real Compose startup

The initial isolated provider test did not run FastAPI lifespan. FastAPI 0.142.2 adds its own
HTTP exporters during startup even when application providers already exist, appending `/v1/traces`
and `/v1/logs` to `http://otel-collector:4317`. The error was reproduced in the real application;
it was not resolved merely by rebuilding the prior source.

Added `test_application_lifespan_does_not_install_http_exporters`: start the real app through
TestClient with only database/S3 lifespan work replaced and HTTP exporter constructors intercepted.
The test failed before the fix, recording `http://collector.test:4317/v1/traces`, then passed after
explicitly disabling native telemetry in the FastAPI constructor. No installed library was modified.
